# 词典序后处理：计划

这一阶段不改第五轮可行性求解。默认引擎仍是 `baseline`。`engine="stable"` 的策略链、目录 CP-SAT 和按需阶段保持原样，时限仍是 15 秒、15 秒、60 秒。优化是显式打开的后处理：没有打开时，求解结果与第五轮相同。

本文件在任何优化试算之前写定。试算名单在 `docs/opt-pilot-split.json`，选定规则写在下面，不按试算结果增删。

## 目标和规格差异

用户确认的词典序是：

1. 用料长度
2. 焊口数
3. 拼法种类
4. 切法种类

利用率只写入结果，不作为约束，也不进入比较键。小者胜。

拼法种类是整组上的有序段序列，含 0 接头整管，不含管身份。切法种类是定尺长度加上排序后的料段。这与 `a7e7c43` 的 lexcg 评估和 `docs/stable-round5-vs-legacy.csv` 相同。

`docs/SPEC.md` 第二节的车间顺序是拼法种类、焊口、切法种类、利用率。本阶段按用户确认的顺序做实验，不改 SPEC，也不把这次实验说成 SPEC 已切换。

## 不退化

后处理的起点是同一次 stable 求解得到的、并且独立校验通过的方案。新方案必须同时满足：

- 独立校验通过
- 词典序键不大于起点（用料、焊口、拼法种类、切法种类依次比较）

任一不满足，就保留起点，不把失败的后处理记成新覆盖。第五轮已覆盖的 1521 / 1591 = 95.60% 不得下降。未解出的题不会被后处理标成不可行。

用料下降时，焊口或种类可以上升，因为词典序先看用料。用料没有下降时，焊口不得上升；前两项都没有下降时，拼法种类不得上升；前三项都没有下降时，切法种类不得上升。

## 三层

主问题沿用 PR #1 `backend/app/lexcg.py` 的耦合模型：焊法列 `x[p]`、切法列 `y[q]`、激活变量，段供给等于段消耗，库存和必用料约束与 lexcg 相同。目标利用率不加进模型。

列的来源只有两类，都打上标记：

- `stable-incumbent`：起点方案里的拼法和切法。这是本公司求解结果，不是老软件方案。
- `native-seed` / `pricing`：lexcg 按本题管长、定尺、锯缝和禁焊区生成的列，以及至多 3 轮既约费用定价。

不读老软件切法，不按题号、材料组或具体段长分支。lexcg 原来的 `_solve_group_fallback` 热启动不用，避免另一套启发式把预算吃掉。

每层到点就停，保留该层目前词典序最好的可行解。某一层 MIP 没有证明最优，也把已得到的值锁住，进入下一层。不把未证明最优写成 `lexicographic_optimal`。随机种子固定为 1，SCIP 线程数固定为 1。

| 层 | 预算 | 做什么 |
| --- | ---: | --- |
| 1 用料 | 20 秒 | 先放起点列，再用最多 12 秒做 lexcg 播种和定价，剩下的时间最小化用料。约束是用料不超过起点。 |
| 2 焊口 | 20 秒 | 用料锁定为第 1 层的值，最小化焊口。不再重新播种。 |
| 3 种类 | 20 秒 | 用料和焊口锁定为前两层的值。先最小化拼法种类，再把剩余时间用于最小化切法种类。 |

三层预算彼此独立，都不占用策略链、CP-SAT 或按需阶段的时钟。三层合计硬上限 60 秒；单题再加起点求解的 15 + 15 + 60 秒。进程硬闹钟是这些预算之和再加 20 秒。

## 试算名单

50 条在打开后处理之前从开发用数据里冻结，规则如下：

- 第五轮可行且校验通过
- 老软件方案在 `docs/stable-round5-vs-legacy.csv` 里几何合规
- 记录号不在种子 `20261013` 的盲测集
- 对老软件的词典序结果是负
- 按（用料差，焊口差，拼法差，切法差）从大到小取 50 条

名单是 `docs/opt-pilot-split.json`。盲测集不进入名单，也不用来改预算、列上限或定价轮数。试算使用 3 个进程。

## 验收

试算要交 `docs/opt-pilot-report.md` 和逐题 CSV，然后停下，不跑 1591。报告写：

- 每层相对起点的用料、焊口、拼法种类、切法种类变化（改进条数、变差条数、合计差）
- 起点和最终保留方案各自对老软件的胜、平、负
- 每层用时的中位、P90、最大
- 校验失败、后处理被弃用、起点复算与第五轮 CSV 四项不一致的条数

后续全量才看的目标，这次试算不声称达到：覆盖率不低于 95.60%，每条已解方案词典序不差于第五轮，并且全量对老软件的胜场不少于负场。
