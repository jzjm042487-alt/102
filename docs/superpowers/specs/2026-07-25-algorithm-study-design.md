# 算法学习与项目审查结对系统设计

## 1. 目标

在现有蛇形管排料项目内建立一套可持续的算法学习流程，使学习者最终能够：

1. 理解算法和优化建模的基础概念。
2. 独立把行业问题翻译成输入、状态、约束和目标。
3. 独立手写核心 Python 算法，而不只是阅读生成代码。
4. 将基础算法映射到当前项目的生产实现。
5. 审查现有实现的正确性、适用范围、性能和测试覆盖。
6. 在证据充分时输出生产代码、测试和审查结论。

该系统不是独立教学产品，也不修改求解器行为。它是当前仓库中的隔离学习区。

## 2. 设计原则

- 学习者拥有核心算法代码。Codex 默认不填写或覆盖 `study.py` 中的待练习实现。
- 每个概念都经过讲解、输入构造、独立编码、测试、评估和项目关联。
- 讲解使用管料或切割场景，避免与项目脱节的抽象例子。
- 先掌握基础算法，再进入整数规划、集合覆盖、列生成和 Arc-flow。
- 测试通过不是唯一标准；学习者还需要解释算法、分析复杂度并在新输入上复写关键代码。
- 学习代码不被生产模块导入，避免训练过程影响 API 和求解结果。

## 3. 目录结构

第一轮恢复性诊断使用：

```text
learning/
└── 00_diagnostic/
    ├── lesson.md
    ├── study.py
    ├── inputs.py
    ├── test_study.py
    ├── assessment.md
    └── project_map.md
```

文件职责：

| 文件 | 所有者 | 职责 |
| --- | --- | --- |
| `lesson.md` | Codex | 概念、手算案例、接口合同和练习要求 |
| `study.py` | 学习者 | 独立编写核心算法 |
| `inputs.py` | Codex | 公开输入、边界输入和项目形状输入 |
| `test_study.py` | Codex | 自动测试；第一版完成后可增加迁移测试 |
| `assessment.md` | Codex | 记录能力证据、提示等级和下一步建议 |
| `project_map.md` | 双方 | 记录基础算法与生产代码的对应关系及审查结论 |

后续课程采用 `learning/NN_topic/`，保留每一课的代码和评估，不覆盖历史练习。
创建或更新课程脚手架时，如果 `study.py` 已经存在，必须原样保留。除非学习者明确要求，否则 Codex不得修改该文件。

## 4. 单课操作流程

### 4.1 概念讲解

每课讲解包含四层：

1. 行业语言：该问题在管料加工中的含义。
2. 算法直觉：算法解决什么问题、为什么可能有效、何时失效。
3. 数学表达：输入、状态、选择、约束和目标。
4. Python 基础：实现所需的数据结构、控制流和函数写法。

讲解可以展示同类小例子和基础语法，但不提前给出本课待测函数的完整实现。

### 4.2 构造输入

编码前明确函数合同，包括：

- 输入类型和单位。
- 元素能否重复使用。
- 空输入、非法值和超长元素的处理。
- 输出是最优值、选择结果，还是两者都要。
- 多个同样最优的结果如何确定顺序。

每课至少提供：

- 一个正常输入。
- 一个边界输入。
- 一个包含重复值的输入。
- 一个能揭示算法缺陷的反例。
- 一个接近当前项目数据形状的输入。

### 4.3 学习者编码

Codex 创建函数接口、文档和测试辅助代码。学习者编辑 `study.py`。

遇到困难时按以下等级提供帮助：

1. 概念提示。
2. 数学关系或状态提示。
3. 伪代码提示。
4. 经学习者明确要求后提供参考实现。

评估记录实际使用的最高提示等级。

### 4.4 代码测试

测试分两轮：

1. 学习者使用公开输入手动运行并观察输出。
2. 第一版完成后，Codex增加未提前展示的迁移输入并运行自动测试。

测试失败时依次确认实际输出、期望输出、首个错误状态以及错误类别。核心算法修改仍由学习者完成。

### 4.5 能力评估

每课从以下维度记录证据，不只给总分：

- 概念理解。
- 手算能力。
- Python表达。
- 算法正确性。
- 边界处理。
- 复杂度意识。
- 调试能力。
- 独立完成程度。
- 提示使用等级。

诊断用于调整讲解速度，不永久跳过基础概念。

### 4.6 项目关联和审查

基础练习通过后，双方定位当前项目中的对应函数，并回答：

- 生产代码采用了哪种算法或数据结构。
- 基础算法中的状态和选择对应哪些业务对象。
- 实现在哪些输入上正确。
- 哪些反例、边界或规模可能导致失败。
- 现有测试是否覆盖这些风险。
- 是否有足够证据提出生产修改。

只有在项目审查形成明确结论后，才进入生产代码修改。修改仍需单独测试和验收。

## 5. 课程地图

### 阶段 A：Python 算法基本功

1. 函数、条件、循环与断言。
2. `list`、`tuple`、`dict` 和 `set`。
3. 排序、计数、分组和不可变输入。
4. `dataclass` 表示订单、原料和方案。
5. 递归、调用栈和测试调试。
6. 时间复杂度与空间复杂度。

### 阶段 B：经典算法

1. 穷举与解空间。
2. 贪心算法及其不变量。
3. 贪心反例与局部最优。
4. 0/1 背包。
5. 完全背包与多重背包。
6. 动态规划的状态、转移和边界。
7. 动态规划路径恢复。
8. 回溯与剪枝。
9. 分支定界。
10. 图、最短路和流模型基础。

### 阶段 C：优化建模

1. 决策变量、约束和目标函数。
2. 线性规划与整数规划。
3. Cutting Stock 与切法列。
4. 集合覆盖和集合分割。
5. 激活变量与 Big-M。
6. 严格词典序优化。
7. 列生成与背包定价子问题。
8. Arc-flow 与状态图压缩。

### 阶段 D：当前项目实战

1. 对照 `docs/SPEC.md` 还原业务模型。
2. 审查拼法候选生成。
3. 审查切法候选生成。
4. 审查段长供需平衡。
5. 审查库存、必用料和焊接限制。
6. 审查严格词典序目标。
7. 审查 verifier 与求解器的一致性。
8. 对比 baseline、route3、v4、global 和实验路线。
9. 用历史失败样本定位建模或搜索问题。
10. 输出经过测试的生产改动和审查报告。

## 6. 首轮恢复性诊断

首轮不使用严格限时，采用半开卷方式：

- 可以查询 Python 语法和标准库。
- 不查询背包或动态规划的现成答案。
- 可以向 Codex请求分级提示。

诊断包含四项连续任务：

1. 将订单明细汇总为 `{长度: 数量}`。
2. 编写最长优先的单根原料贪心装入。
3. 使用容量 `10` 和管段 `[6, 5, 5]` 解释并复现贪心反例。
4. 编写 `best_fill(capacity, lengths)`，方法不限，返回最优选择。

### 6.1 诊断函数合同

任务 1 使用：

```python
def aggregate_demands(order_lines: list[tuple[int, int]]) -> dict[int, int]:
    ...
```

- 每个元组是 `(length, quantity)`，两者都必须是正整数，否则抛出 `ValueError`。
- 相同长度的数量相加。
- 空输入返回空字典。
- 返回字典按长度从小到大的插入顺序构造，便于稳定测试。
- 不修改传入列表。

任务 2 使用：

```python
def greedy_fill(capacity: int, lengths: list[int]) -> list[int]:
    ...
```

- `capacity` 必须是正整数，所有段长必须是正整数，否则抛出 `ValueError`。
- 列表中的每个位置代表一根可使用一次的管段；相同数值的元素仍是不同管段。
- 按长度从大到小依次检查，能够放入剩余容量时就选择。
- 超过原料容量的元素不是非法输入，但不能被选择。
- 返回选中段长组成的降序列表；空输入或没有可选段时返回空列表。
- 不修改传入列表。

任务 3 不增加新函数。学习者先手算，再使用任务 2 的函数得到 `[6]`；完成任务 4 后使用同一输入得到 `[5, 5]`。原因解释记录在 `assessment.md`。

任务 4 使用：

```python
def best_fill(capacity: int, lengths: list[int]) -> list[int]:
    ...
```

- 输入合法性、重复元素、超长元素和不修改输入的规则与 `greedy_fill` 相同。
- 首要目标是在总长度不超过 `capacity` 的前提下，使选中段长总和最大。
- 总长度相同时，优先选择段数更少的方案。
- 总长度和段数都相同时，将方案按降序排列并选择字典序更大的方案。
- 返回按降序排列的选中段长；空输入或没有可选段时返回空列表。
- 实现方式不限，可以使用穷举、递归、动态规划或其他正确方法。

首轮重点区分：

- Python语法生疏。
- 算法思维生疏。
- 能描述思路但不能稳定转成代码。
- 能写代码但缺少边界和复杂度意识。

诊断结果决定阶段 A 的讲解密度，以及阶段 B 从穷举还是贪心开始。

## 7. 测试与完成标准

每课完成需要同时满足：

1. 公开测试通过。
2. 迁移输入测试通过。
3. 学习者能解释关键状态和每个分支。
4. 学习者能说明至少一个错误方案或反例。
5. 学习者能分析主要时间复杂度。
6. 学习者能在关闭参考资料后复写核心部分。
7. `project_map.md` 记录了生产映射或明确说明暂时没有映射。

如未满足，不判定为失败，而是记录需要补强的层级并安排更小的下一练习。

## 8. 范围边界

本设计不包含：

- 自动生成整套课程答案。
- 用学习代码替换生产求解器。
- 为学习进度制作独立前端。
- 建立分数排名或强制时间限制。
- 在缺少测试证据时重构生产算法。

第一阶段只实现 `learning/00_diagnostic/`。后续课程目录根据诊断结果逐课创建。
