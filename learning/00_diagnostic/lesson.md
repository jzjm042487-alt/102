# 第 0 课：恢复性诊断

这不是考试，也不要求你已经记得某种标准算法。它要观察三件事：

1. 你能否把业务描述整理成明确的输入和输出。
2. 你能否把一个逐步决策过程写成 Python。
3. 当局部规则不能保证最优时，你会怎样寻找完整解。

核心代码由你写在 `study.py`。先手算，再编码，再运行测试。

## 一、什么是算法

算法可以先理解成：

> 一组有限、明确、可执行的步骤，把输入转换成输出。

“尽量排得好一点”不是算法，因为“尽量”和“好一点”都不明确。

下面才接近算法：

> 将候选管段按长度从大到小排列，逐个检查；如果当前管段不超过原料的剩余长度，就选中它。

这句话说明了：

- 输入是什么：原料容量和候选管段。
- 处理顺序是什么：从长到短。
- 每一步做什么：比较当前段长与剩余容量。
- 状态如何变化：选中后扣减剩余容量。
- 什么时候结束：所有候选管段都检查完。
- 输出是什么：选中的管段。

## 二、先区分三个概念

### 1. 可行解

满足全部硬性条件的方案。

若原料长度是 `10`，选择 `[6, 4]` 是可行解，因为：

```text
6 + 4 = 10
```

选择 `[6, 5]` 不是可行解，因为：

```text
6 + 5 = 11 > 10
```

### 2. 目标函数

目标函数告诉算法：多个可行解中，哪个更好。

本课的首要目标是：

```text
在总长度不超过 capacity 的前提下，让选中长度之和最大。
```

### 3. 最优解

目标函数取到最好值的可行解。

“可行”只表示能用；“最优”表示没有其他可行方案在当前目标下更好。

## 四、任务 1：订单汇总

输入：

```python
[(6000, 2), (3000, 1), (6000, 3)]
```

每一项表示：

```text
(长度, 数量)
```

| 读到的记录 | 当前累计结果 |
| --- | --- |
| `(6000, 2)` | `{6000: 2}` |

| `(6000, 3)` | `{6000: 5, 3000: 1}` |

```python

```

## 五、任务 2：最长优先贪心

原料容量：

```text
10
```

候选管段：

```python
[6, 5, 4]
```

先按从大到小排列，然后逐个判断：

| 当前管段 | 放入前剩余容量 | 是否选择 | 放入后剩余容量 |
| ---: | ---: | --- | ---: |
| 6 | 10 | 是 | 4 |
| 5 | 4 | 否 | 4 |
| 4 | 4 | 是 | 0 |

结果：

```python
[6, 4]
```

### 贪心算法

贪心算法在每一步选择“当前看起来最好”的动作，并且通常不撤销之前的选择。

这里的局部规则是：

```text
选择当前能够放入的最长管段。
```

实现过程中至少要保持三个不变量：

1. 已选总长度始终不超过容量。
2. 每个输入位置最多使用一次。
3. 剩余容量始终等于容量减去已选总长度。

不变量是在循环每一步之后都应保持为真的条件。它是理解和审查算法正确性的核心工具。

## 六、为什么贪心不一定最优

看下面的输入：

```python
capacity = 10
lengths = [6, 5, 5]
```

最长优先贪心首先选择 `6`，剩余容量是 `4`。两个 `5` 都无法再放入：

```text
贪心结果 = [6]
利用长度 = 6
```

但是存在另一个可行解：

```text
[5, 5]
5 + 5 = 10
```

所以：

```text
局部最优选择 6
并没有导向全局最优方案 [5, 5]
```

这不是 Python 写错了，而是算法策略本身不能保证全局最优。

## 七、怎样保证找到最优解

最直接的方法是检查所有可能的选择组合。

对每根管段都只有两个选择：

```text
选
不选
```

三个元素形成一棵二叉决策树：

```text
                    开始
              /               \
           选 6               不选 6
         /     \              /      \
      选 5    不选 5       选 5     不选 5
      / \       / \         / \        / \
   选/不选   选/不选     选/不选    选/不选
   最后一个 5
```

三个元素最多有：

```text
2 × 2 × 2 = 2³ = 8
```

种选择。

枚举所有组合后：

1. 排除总长度超过容量的组合。
2. 比较剩余组合的总长度。
3. 总长度相同时，按约定的规则决定唯一输出。

这就是穷举思维。它可能很慢，但容易验证正确，也是以后理解动态规划为何能“避免重复计算”的基础。

## 八、三个函数的合同

### `aggregate_demands`

```python
def aggregate_demands(order_lines: list[tuple[int, int]]) -> dict[int, int]:
```

- 每项是 `(length, quantity)`。
- `length` 和 `quantity` 必须是正整数，否则抛出 `ValueError`。
- 相同长度的数量相加。
- 空列表返回 `{}`。
- 返回字典的键按长度升序插入。
- 不修改传入列表。

### `greedy_fill`

```python
def greedy_fill(capacity: int, lengths: list[int]) -> list[int]:
```

- `capacity` 和所有段长必须是正整数，否则抛出 `ValueError`。
- 每个列表位置代表一根只能使用一次的管段。
- 相同长度的两项代表两根不同管段。
- 按长度从大到小检查，能放入就选择。
- 超过容量的正数段长直接跳过。
- 返回选中段长组成的降序列表。
- 空输入或没有可选项时返回 `[]`。
- 不修改传入列表。

### `best_fill`

```python
def best_fill(capacity: int, lengths: list[int]) -> list[int]:
```

- 输入规则与 `greedy_fill` 相同。
- 首先让选中段长总和最大。
- 总和相同时，选择段数更少的方案。
- 总和与段数都相同时，把方案降序排列，选择字典序更大的方案。
- 返回降序列表。
- 方法不限，可以穷举、递归、动态规划或使用你自己想到的方法。
