# 第 0 课项目映射

## 基础算法

本课的 `greedy_fill` 使用“当前剩余容量内选择最长元素”的局部规则。

## 生产代码位置

对应入口：

```text
backend/app/solver.py::_generate_cut_candidates
```

该函数的“seeded best-fill patterns”部分从一个 `seed` 开始，然后反复使用二分查找选择当前容量内最大的可放入段长。

## 相同点

- 都维护剩余容量。
- 都反复选择当前能放入的最长段。
- 都使用局部选择快速构造一个可行组合。

## 生产代码增加的条件

- 刀缝 `blade_margin`。
- 每一种起始段都可以作为 `seed`。
- 单段、互补二段和重复段等其他候选来源。
- 候选数量上限和超时限制。
- 稳定去重和按余料排序。
- 候选生成以后还有整数规划负责全局选择。

## 当前审查结论

容量 `10`、管段 `[6, 5, 5]` 能证明“单次最长优先贪心”不保证全局最优，但不能直接证明生产求解器存在同样的错误。生产代码会尝试多个种子和其他候选来源。

完成本课后，需要把该反例扩展成符合刀缝和候选池规则的项目测试，再判断生产候选生成是否遗漏关键切法。
